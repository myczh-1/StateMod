# 失败复核：冻结成绩与设计限制分开

本报告仅分析本轮已保存数据，没有新模型前向、没有修复输出或重新评分。正式结果仍是CAPABILITY_OR_COVERAGE_LIMITED，未通过独立闭环确认。

## 1. 判断失配是实际发生的

全部32项均有合法窗口与实际判断读出。E两套措辞各接受8/8；N的W3只拒绝6/8，W4拒绝0/8。共10项N错误启用，均有14层实际Bank访问记录。未人工纠正模块，也未改0.5阈值。

N真实要求返回对象可继续修改，因此其不应被外部frozenset偏好强制覆盖；下述.add评分接口问题不把N改成E。W4普遍失配是本轮观察，不能据此证明特征只学习长度或关键词，也不能当成模型不存在相关信息的证据。

## 2. 人工选择也未复现旧开发V收益

人工V的E精确frozenset为4/16，联合正确3/16；无注入E联合为0/16。人工V相对无注入产生5项E功能退化，同时修复3项原失败，E功能总数由12降至10。模块在全部E都启用，因此其E生成与人工V一致。

三个联合成功为：python_literal_representation_E_W3、centered_text_padding_E_W3、modal_member_selection_E_W4。没有一个计算族在两种措辞下都联合成功。不能仅把本轮失败归因于B；冻结V在这些新任务上的行为效果同样不足。

实际错误例子：
- tab_stop_expansion_E_W4从处理后字符串集合变为`set('\\n'.join(...))`，把字符串成员拆成字符，产生成员计算错误。
- integral_float_predicate_E_W3/W4的V输出出现无对象`is_integer()`及非法重绑定推导式变量的赋值表达式，编译/执行失败。这不是评分器缺少一个合法内置方法。
- centered_text_padding_E_W4出现`center(...)`未定义的函数调用，实际执行失败。

完整未修改代码与逐测试失败保存在evaluation/SCORED_RESULTS.json。E功能退化判据不依赖N的.add接口，不能用N评分设计问题抹去这5项退化。

## 3. N的提示合同与评分接口不完全对齐

这是准备阶段的设计缺口：新N措辞强调“往里面放/移走成员”“同一个返回对象”“插入和删除”，却没有明确要求Python `.add()`方法；冻结评分器仍要求实际执行`.add()`和`.remove()`。list支持原地append/remove，未必违反提示中写出的可变性要求，但没有.add。

BASE有6项记录仅因list缺少.add而失败，成员值、类型、去重、不改输入检查均已通过：

- dna_reverse_complement_N_W3 / W4
- integral_float_predicate_N_W3
- modal_member_selection_N_W4
- python_literal_representation_N_W3 / W4

例如`return list({repr(t) for t in texts})`被报告为`AttributeError: 'list' object has no attribute 'add'`。不能把这6项直接解释为模型不懂可变性。准备时gold全通过只证明金标准实现满足评分器，未充分覆盖提示—评分接口的一致性检查。

本轮不将其改计成功，不重新定义冻结门槛，也不据此筛出一个更好看的子集。正式BASE N仍为1/16，覆盖门槛未满足；该数字只对本轮冻结的具体接口合同成立。除了这6项，仍存在计算、调用错误及截断，不能把所有失败归因于.add。

## 4. 文字参考也必须保留边界

TEXT_CODE为本轮直接生成完整函数的可见条件提示：E联合9/16，N冻结合同0/16，其中12/16 N实际返回不可变frozenset。这12项存在真实可变性冲突，不是list方法名评分差异。

该文字组不是此前24/24正确的“frozenset选项在前”二选一判断老师。旧选择题成绩与本轮函数生成成绩不能混用；本轮没有新增运行那个选择题老师，因此不声称已测得模块对其新任务判断的一致率。文字参照按已冻结提示执行，未因结果差更换问法。

## 5. 结论约束

工程接线、数值检查和实际访问可以通过，但行为独立确认未通过。当前数据同时出现新措辞匹配失配、新任务V功能退化以及提示—评分接口不完全对齐，不能用单一原因覆盖全部失败。保留旧Cloud03开发成功，不追认本轮成功，也不据此否定所有潜在状态方法。
