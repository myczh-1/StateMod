# C：构造器 Token 历史与单步干预历史

结论：`TOKEN_HISTORY_EFFECT_CONSISTENT`。在字符计数这个反例中，给定frozenset构造器后，即使没有Bank状态影响，也足以进入非法计数续写；单次干预历史不是该错误出现的必要条件。

## 自然复现

原OFF正确set程序、原ON非法frozenset程序的完整Token序列均精确复现。两者都自然生成。原ON只在return后的第一次预测使用Bank，14个层各访问一次。

## 四格诊断

|当前预测时是否干预|固定构造器|后续真实贪心生成的功能|错误/结果|
|---|---|---|---|
|OFF|set|通过|集合推导式中sum逐字符串计数|
|ON一次|set|通过|与OFF_SET完整Token输出相同|
|OFF|frozenset|失败|`count := ... for count ...`非法绑定|
|ON一次|frozenset|失败|同类非法绑定|

四条只强制构造器Token，未提供括号、参数、计数算法或正确答案。强制Token计入原96 Token预算。这些是机制诊断，不计自然生成规则成功。无法执行的frozenset代码，实际返回类型记不可评估，不能因文本出现frozenset计为EXACT_TYPE成功。

OFF_SET与自然OFF，ON_FRO与自然ON，均做到完整Token、Logits及最终缓存精确一致。这验证了强制分支在自然选择相同Token时的工程重建。

## 内部状态仍有可测影响，但没有在本四格中增加功能失败

同样构造器、完全相同Token历史下，在构造器结束位置：

|构造器|ON/OFF全词表Logits RMS|下一Token第一名|
|---|---:|---|
|set|0.384029|两边同为`({`|
|frozenset|0.464095|两边同为`(count`|

这些是有意改变干预条件的因果差，不是Cached/Fresh数值误差；不能拿0.001数值门槛判断它们不合格。缓存首次差异在零编号Block15的Key出现，与Bank作用于Block14输出、进而影响后续层历史一致；不解释为独立语义定位。

OFF_FRO与ON_FRO第一次生成分歧在零编号第36步：无Bank选择`count` Token，有Bank选择空格Token，随后接`0`，形成`else count`与`else 0`。在此前完全相同历史下，`count`对空格的Logit间隔由+0.160976变为−0.096485。说明单步干预留下的状态确实会影响更晚的自然选择。

但是两边在这次晚期分歧之前，都已经生成非法的赋值表达式与同名迭代变量。ON_SET虽有内部数值变化，功能仍正确。因此不能将原错误主要解释为“Bank持续访问破坏了计算”或“只要有这次内部干预就必然计算错”。

## 因果解释边界

本反例支持：原V促成了构造器切换，而模型在该上下文下对frozenset的续写路径本来就不可靠。此处类型切换足以触发错误，额外内部状态影响不是必要条件。

这没有免除自然ON的功能退化：自然运行是Bank把原正确程序带到错误程序。也不能推广为所有V退化都只来自Token历史。OFF_SET与OFF_FRO的比较包含构造器Token数量、绝对位置与自回归历史差异，不是纯语义替换。

不延长注入、不改Bank、不调整剂量，不追加其他任务。本轮止于该反例的机制定位。
