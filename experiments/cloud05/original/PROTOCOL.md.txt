# Cloud05：简单计算固定后的措辞对照

日期：2026-11-05。状态：仅准备方案、任务与本地合同检查，尚未运行模型、未连接服务器。

## 1. 本轮只回答什么

在同一简单计算、相同函数签名、相同执行用例下，改变可变性合同的表述，判断与 V 是否仍稳定？先建立这个基础，再考虑提高任务难度。

这是已见开发族的机制复核，不是新的独立确认。不以此改写 Cloud03 开发成功或 Cloud04 未确认。模块、阈值、Bank、窗口均不变。没有新训练、重编译或强度搜索。

本轮不加入困难题，因此不能单独测出“复杂度导致多少下降”。若简单题在新措辞下仍失败，说明复杂计算不是失败的必要条件；若简单题稳定，只能说明原失败尚未在此复现，不能直接断定全由难度造成。

## 2. 固定四个简单计算族

直接取 Cloud03 已运行的 double、increment、negative、lower：整数乘二、加一、取负、字符串小写。每题仅一次逐成员变换加去重，不增加嵌套数据、频数统计、边界分支或额外算法。每族 E/N 计算体和测试完全相同。

每族两种合同、两版措辞，共16个输入：

- E：无需返回后增删；set 是合法基本结果，frozenset 是外部偏好。
- N：须在同一返回对象上调用 `.add()` 和 `.remove()`；保留成员且完成增删恢复。
- W_ANCHOR：完整保留原 W2 Prompt，作为旧成功复现锚点。
- W_LIFECYCLE：仅替换合同句为生命周期表述，保留同样的明确 API 要求。任务主体、格式后缀、签名和测试不变。

W_LIFECYCLE 固定文本：

E：`生命周期约定：读取完毕后，调用方不会继续对返回对象添加或移除成员；无需提供 .add() 和 .remove()。`

N：`生命周期约定：读取完毕后，调用方会继续对返回对象添加和移除成员；须提供 .add() 和 .remove()。`

这里测试的是**对齐 API 合同后的表达变化**，不是重跑原 Cloud04 W4。两版正文不直接指定 set/frozenset。真实 Token 长度全部记录；不添加无意义填充硬凑等长。因此“措辞变化”仍包含文字、长度和位置变化，不声称纯语义隔离。

## 3. 四条件，固定64条逻辑生成

| 条件 | 用途 |
|---|---|
| BASE | 无规则、无Bank；读出判断分数但不执行 |
| TEXT_CODE | 沿用同一文字规则，观察完整代码能力 |
| MANUAL_V | E人工开启、N关闭；隔离 V 本身效果 |
| MODULE_V | 原模块 p>0.5 时开启，否则关闭 |

4族 × 2合同 × 2措辞 × 4条件 = 64条生成记录。BASE/MANUAL/MODULE 使用相同 Prompt 和同一原生 return 前检查点分叉，缓存独立；TEXT 独立运行。共享前缀和审计重算不计成额外样本，但应记录实际前向成本。

TEXT_CODE system保持：`返回结果需要支持增删时，使用 set。\n返回结果不需要支持增删时，使用 frozenset。` 它是代码生成参照，不是此前24/24的选择题老师。文字组失败保留，不因此换问法。

只复用原自然生成、FIRST_DECISION_ONLY、单函数格式合同，不提供正确代码前缀、不强迫构造器、不修复代码。未到 Gate 或首return前已经选好返回容器，计覆盖不足，不能作为安全拒绝。64条全部保留，不按结果换题或筛掉某一措辞。

## 4. 评分合同先对齐

沿用原评分器，不放宽历史标准：

- E：精确成员值与成员类型、唯一性、不修改输入；JOINT另要求实际精确frozenset。正确set计功能正确。
- N：同样检查成员，且实际 `.add(marker)`、查询、`.remove(marker)`、恢复成员和对象身份。两种提示均明示对应API，不再用模糊“能修改”要求代替。
- 格式、编译/调用错误、成员错误、增删失败、截断分别列示。任何原因导致 BASE正确→处理后错误，都计新增功能退化。

每族沿用原冻结的空输入、重复、边界用例；不增加新测试难度。准备时只运行人工gold与明确负例的本地执行检查，不运行模型。检查E合法set不被误判功能错、E的frozenset达到JOINT、N的set通过、N的list/frozenset失败。负例只是评分器检查，不作为模型输入或训练数据。

## 5. 预定指标与停止标准

统计单位为4个计算族，两版措辞是重复测量。每版分别给出4项E、4项N，不能合并后掩盖某一版失败。不设显著性或总体泛化声称。

1. **复现锚点**：W_ANCHOR 的BASE/MANUAL/MODULE逐题与旧完整Token比较；同历史Logits采用旧容差。原本正确的锚点行为不能复现时，记录 `ANCHOR_NOT_REPRODUCED`，先停止升级难度，不能将新措辞差异作有效归因。保留全部已经执行的数据。
2. **基础难度可用**：每版BASE的E功能≥3/4、N合同≥3/4，窗口覆盖单列。否则 `SIMPLE_BASELINE_NOT_STABLE`；不筛出成功子集宣称稳定。
3. **判断稳定**：每版E接受≥3/4、N拒绝4/4，全部拒绝须有合法读出；公布同族判断翻转、原分数、距固定阈值的距离，不重新选阈值。
4. **人工V稳定**：每版E JOINT≥3/4、相对BASE净新增JOINT≥2、全部BASE原正确E/N零新增功能退化；全部8项E实际访问原Bank一次。公布是否达到4/4，而不只报最低门槛。
5. **AUTO**：分别给出与MANUAL的差距、错误启用和N真实访问次数。只有判断与MANUAL均稳定，AUTO也满足同样行为标准且N零访问，才标记当前开发矩阵闭环稳定。不据此追认历史R2或独立泛化。

这些门槛在完整矩阵后判定；只有工程/数值硬失败才提前停止，其余未运行记NOT_RUN，不记零成功。任何失败均停止本轮后续扩题或难度升级，不重采样、不改阈值、不换载荷。

主要对照是每族同合同的 W_LIFECYCLE−W_ANCHOR：分别比较B启停、MANUAL首步作用和真实功能，不从AUTO一个总分猜原因。Bank首步记录fro/set/list真实首Token排名、同检查点Logit变化；不冒充完整表达式概率。Attention仍按固定全部层/Head报告，不挑最佳Head。
